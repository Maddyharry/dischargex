# การรับปัญหาจาก Auto และนำไปแก้โปรแกรม

อัปเดต 10 กันยายน 2026 — ชุดเผยแพร่เว็บ 2f584e7

## สิ่งที่ทำได้ในรุ่นนี้

- โปรแกรม v0.12.9 ส่งรายงานผ่านบัญชีที่ล็อกอินมายัง `/api/automator/incidents` ได้เมื่อผู้ใช้เลือกส่ง
- ผู้ดูแลเปิด `/admin/automator` ดูรายงานล่าสุด 100 รายการ และจำนวนปัญหารูปแบบเดียวกันในรายการที่แสดง
- รายงานมีรุ่นโปรแกรม, ประเภทปัญหา, ลำดับชนิดการกระทำ, เวลา, รุ่น Windows และขนาดหน้าจอ ไม่มีข้อความที่กรอก, clipboard, ภาพหน้าจอ หรือชื่อผู้ป่วย
- ส่งซ้ำรายงานเดิมไม่เพิ่มรายการใหม่ บัญชีต่างกันแยกรายงานจากกัน หากส่งไม่สำเร็จโปรแกรมเก็บรายงานไว้ในเครื่อง
- จำกัดการรับประมาณ 30 รายงานต่อบัญชีต่อชั่วโมง (ยังไม่ใช่ตัวจำกัดแบบ atomic สำหรับคำขอพร้อมกันจำนวนมาก)

## เมื่อมีรายงานเข้ามา

1. ดูประเภทปัญหา รุ่นโปรแกรม และลำดับก่อนหยุด เช่น ClipboardUnavailable หรือ HosXpUnresponsive
2. สร้างสถานการณ์จำลองโดยไม่ใช้ข้อมูลคนไข้จริง แล้วเพิ่มการทดสอบที่ทำให้เห็นข้อผิดพลาดเดิม
3. แก้เงื่อนไขตรวจหน้าต่าง/การรอ/การกู้ clipboard ไม่เพิ่มการกด Tab หรือวางซ้ำโดยไม่ยืนยันตำแหน่ง
4. ทดสอบซ้ำทั้งเส้นทางปกติ, หยุด F10, พัก F9 และกรณี HOSxP ไม่ตอบสนอง
5. ออกรุ่นใหม่พร้อมบันทึกวิธีแก้ ผู้ใช้ตรวจรุ่นและดาวน์โหลดจาก GitHub ทางการ

รายงานช่วยหาสาเหตุ แต่ยังไม่สามารถยืนยันตำแหน่ง cursor หรือสิ่งที่บังหน้าจอได้โดยไม่มีภาพ/ข้อมูล UI เพิ่มเติม ไม่ใช่ระบบ AI คุมเครื่องเพื่อแก้ทุกอย่างเอง และยังไม่มีการติดตั้งอัปเดตอัตโนมัติ

## วันที่ Admit/Discharge

- ใช้วันที่ที่ระบุชัดก่อน หากไม่มีจึงใช้ขอบเขตวันแรก/วันสุดท้ายของรายการชาร์ตตามแนวทางเจ้าของ พร้อมข้อความให้ตรวจว่าชาร์ตครบ
- แยก F/U, FU, follow up, follow-up และนัดออกจากวันที่ของชาร์ต เก็บ timestamp ของบันทึกที่มีคำสั่งนัดต่อท้าย
- หากขาดวันใด เก็บอีกวันที่พบไว้ ไม่เติมวันที่จากข้อความ AI โดยไม่มีหลักฐาน
- การขอเฉพาะวันที่ซ้ำใช้ข้อมูลต้นทางและไม่คิดค่าสรุปเพิ่ม แต่ยังอยู่ภายใต้สิทธิ์บัญชีเดิม
- การทดสอบใช้ข้อมูลจำลอง ยังต้องตรวจชาร์ตรูปแบบจริงที่โรงพยาบาลก่อนยืนยันครอบคลุมทุกเครื่อง

## สิ่งที่ยังไม่เปิด

- ภาพหน้าจอส่งอัตโนมัติ, AI แก้หน้า HOSxP แล้วทำต่อเอง
- ตัวเลขเวลาที่ประหยัดได้จริง: เวลาประมวลผลสรุปไม่ใช่เวลาทำงานรวมของแพทย์
- แพ็กเกจ/ราคาใหม่: รอเจ้าของเลือกก่อนเปิดขาย
