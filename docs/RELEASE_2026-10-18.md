# Release notes — 2026-10-18

## Customer-facing package policy

- New paid periods beginning on or after 2026-10-19 (Asia/Bangkok) use the updated AI usage budgets: monthly Basic 59.8, Standard 118, Pro 218 units; full annual periods 598, 1,198, 2,198 units. Annual monthly equivalents are rounded for comparison only.
- Prices remain Basic 299/2,990 THB, Standard 590/5,990 THB, and Pro 1,090/10,990 THB for monthly/annual billing. Annual equivalents shown to customers are rounded to 249/499/916 THB per month.
- Paid periods started before 2026-10-19 Bangkok time retain their existing terms through renewal. Billing period wording follows Stripe's calendar month or calendar year dates, not fixed 30/365-day promises.
- Daily summary limits are separate hard maximums: Basic 4, Standard 14, Pro 42 cases per day. They do not promise that many completed cases; actual AI budget use varies with text and image size. Customers can view usage and reset timing in `/app/profile`.
- New Boost checkout is removed from pricing, and `/api/stripe/checkout` rejects positive `addCredits` requests server-side. Previously purchased add-on credits remain in place; existing holders may contact support for review. There is no automatic refund.
- Subscription management is integrated in the website profile: the plan picker schedules an eligible plan change for the next paid period through the app-managed Stripe subscription schedule. Renewal cancellation is managed from the website profile/Stripe Billing Portal; customers do not need a separate Stripe account. Stripe's native portal plan-update option remains disabled because the six prices belong to separate products.
- AI Chat is temporarily unavailable. Trial and package copy does not promise AI Chat volume; the Trial summary ceiling is a system maximum, not a guaranteed number of completed cases.
- Usage units are based on token usage recorded by the application. The 5x revenue/API-cost policy uses an FX-based cost estimate target; it is not the provider's final invoice amount, actual profit, or a guarantee of either.

## PWA and privacy handling

- PWA generation is disabled. `/sw.js` is served via a `beforeFiles` rewrite to the new `/privacy-retire-sw.js`; this takes precedence over but does not overwrite the owner-managed `public/sw.js`. The retirement response is no-store and allows root scope.
- The retirement worker skips waiting, deletes only the known next-pwa cache names and exact root Workbox precache cache, claims controlled windows, and unregisters only its own registration. It does not navigate open tabs, has no fetch handler, and does not inspect request contents. Existing pages remain open to protect unsaved work; they use network for future fetches, while the page shell refreshes on the user's next normal navigation or manual reload. If PWA is re-enabled later, retain the existing upload/slip/screenshot/clinical/document/image precache exclusions and `NetworkOnly` rules.
- The root layout loads `/privacy-reset-sw.js` before interactive content. It unregisters only this site's root `/sw.js` registration and removes the known `next-pwa` cache names plus the exact root Workbox precache cache name. It does not clear unrelated registrations or Cache Storage entries.
- Retirement occurs when the browser checks for and installs the `/sw.js` update; a browser that never returns cannot be remotely cleaned. An already-open old page remains until the user navigates or reloads, avoiding loss of unsaved forms. The layout reset remains a secondary cleanup path for returning clients on a subsequent page load.
- Disabling PWA removes offline caching/install behavior until a reviewed service worker is restored. Do not copy the ignored owner `public/sw.js` or generated workbox artifact into a release; the rewrite is the supported retirement path.
- The clinical filename/type exclusion patterns are best-effort, not complete clinical-content detection. User confirmation that an image was reviewed is not pixel-level verification that identifiers were removed; retain the manual redaction warning and avoid promising automatic de-identification.
